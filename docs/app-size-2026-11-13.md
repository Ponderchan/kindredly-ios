# App size, 2026-11-13

The owner: "现在的包大小都100mb了 之后能不能统一优化一下把包的大小变小一些". This is where the
size came from, what branch `app-size` changed, and what is left for him to decide.

## What "100 MB" is

Build 42 (binary 1.2.8, the newest .ipa, `~/Desktop/Kindredly-1.2.8-b42.ipa`):

| | size |
|---|---|
| the app on the phone (what iPhone Storage and the App Store page show) | **95.6 MB** (96.6 MB in disk blocks) |
| the .ipa file | 66.9 MB, but 22.5 MB of it is `Symbols/` (crash symbols for App Store Connect; never sent to phones) |
| the download from the App Store | about 60–70 MB (an estimate: the store encrypts the executable code, which then doesn't compress) |

App thinning gives almost nothing here: the app is arm64 only, iPhone only, and has no image
variants in an asset catalog (the pictures come from the JS bundle, which thinning doesn't touch).

Inside the frameworks, 13.9 of the 31.3 MB was symbol names (the frameworks arrive prebuilt with
their full symbol tables; CocoaPods copies them in as they are).

and RevenueCat's web SDK (used only in Expo Go and on the web) was 0.84 MB. The nine languages'
strings (`src/data/strings*.ts`) are about 2 MB and are needed. Dev pages are 16 KB.

## Fonts (owner, same day: only the four faces)

The app embeds three files, 0.44 MB: Newsreader Regular and Italic and EB Garamond Regular. System
(SF Pro) and SF Mono come with iOS. Settings → Font offers exactly those four. Three places still
asked for a fifth face and now don't: the rating sheet's labels (Menlo → SF Mono), the Live
Activity's line (New York, SwiftUI's serif design → System; an extension can't use the app's
embedded fonts), and the report cards' "z z" (SF Rounded → SF Pro). The seven unused
`@expo-google-fonts` packages are out of package.json; they were never in the app.

## Left for the owner

1. **Take branch `app-size` into 1.0.9.** It needs a new binary to make the app smaller: an
   over-the-air update could carry the JS and WebP parts, but the PNGs already in the installed app
   stay there. Before submitting: one sandbox purchase on TestFlight (the RevenueCat change), and a
   look at the Live Activity on a phone (its line is now in the system font).
2. **Swift compiled for size (`-Osize`)**: measured on a second archive of this branch, the main
   program goes 33.58 → 31.08 MB and the widget 2.35 → 2.24 MB, about −2.6 MB. The code runs a little
   slower; animations would need a pass on a real phone. Not done; recommended only if every MB counts.
3. **Live Activity font**: System now. Newsreader would need its file put into the widget extension
   (+0.24 MB).

Looked at and left alone:

- RevenueCat (5.4 MB of the main program): it is the purchases.
- libavif (3.3 MB after stripping): the AVIF decoder that comes inside expo-image's precompiled
  package. Taking it out means building expo-image from source with a patched podspec; not worth it.
- The nine languages' strings (about 2 MB of JS): loading one language at a time would be a rework
  of i18n for a small gain.
- `Symbols/` in the .ipa (22.5 MB zipped): crash symbols for App Store Connect, never on a phone.
- Dev pages: 16 KB of JS; their films are already left out of release builds.

## How to measure again

- On the phone: unzip the .ipa and `du -sk Payload/Kindredly.app/*`; ignore `Symbols/`.
- Framework symbols: the Release build log prints `[strip] <name>: before -> after bytes` for each
  framework; `nm -a <framework binary> | grep -c ' - '` should be 1 or 0 in a shipped app.
- JS bundle: `npx expo export --platform ios --source-maps --no-bytecode --output-dir <dir>`, then
  attribute bytes to files with the map.
- Main program: build Release with `LD_GENERATE_MAP_FILE=YES` and read `Kindredly-LinkMap-*-arm64.txt`.
